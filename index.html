The comparison trap

Same data. One wrong date.

"Compare to last year" sounds simple. Here is what happens when the rule isn't written down.

Correct comparison
Same week of the year + weekday
Down 73

1,436 now vs 1,509 on Monday 11/10/2025. Monday of week 46 to Monday of week 46.

All 14 checks pass
Wrong comparison
Calendar date + fallback
Up 139

1,436 now vs 1,297 on Monday 11/3/2025. 11/9/2025 was a Sunday with no snapshot, so it quietly fell back a week.

Checker fails it

Both count correctly. Only one answers the question.

Hands on

Try it in 15 minutes

You only need Python 3.9 or later. No packages to install, no database, no account.

01

Get the kit

Use Download the kit above and unzip it, or clone it with Git. Then open a terminal in that folder.

git clone https://github.com/UUBryson/hess-2026-ai-report-kit.git
02

Build the report

Reads the fake snapshots, applies the written rules, and writes an HTML report plus a summary file to report/out/.

python report/build_report.py
03

Check it before anyone sees it

Fourteen checks recount the numbers from the raw file with separate code. Exit code 0 means it is OK to send.

python check/verify.py
04

Prove the checks can fail

A check that can never fail isn't a check. This breaks a copy on purpose and confirms both breaks are caught.

python check/verify.py --challenge
05

Watch it catch the classic mistake

Build the report the wrong way, by calendar date, then run the checker on it. It flags the date and says not to send.

python report/build_report.py --compare-by calendar --out report/out_mistake
python check/verify.py --summary report/out_mistake/summary.json

On Windows, if python isn't found, use py instead. On a Mac, use python3.

The workflow

Five steps to a trusted report

From a report someone builds by hand to one your leadership can trust. Steps 02 and 05 are the ones people skip.

01

Pick the report

One someone builds by hand every week. Registration pacing is a good first one. If it already lives in Power BI or an Excel macro, the rules and the checks still apply.

02

Write the rules down

Sit with the person who builds it and record them walking through last week's report. Turn it into rules/report_rules.md, then read it back to them.

03

Get read-only access

Send your DBA the short request in ACCESS.md. Build against fake or de-identified data first.

04

AI drafts the script

Give an AI tool your school approves the rules file, a sample of the data, and prompts/01_build_report.md. It lists each rule and asks before it guesses.

05

Verify, then hand it back

Run the checks. Show the first real report to the person who used to build it. They are the final reviewer.

FAQ

Questions people ask

If yours isn't here, email us. We're glad to help.

Which AI tool do I need?

Whichever one your institution approves. Claude, ChatGPT, Copilot, Gemini and others all work; the kit is tool-neutral. The rules file does the heavy lifting, and the prompt mostly tells the AI to follow it and to ask instead of guess.

Do I have to know how to code?

You need to be comfortable running a command in a terminal. You don't need to write Python yourself, but you should read what the AI writes and be able to explain each part before you trust it. The reference script is short on purpose.

What about FERPA and student data?

Build and test on fake or de-identified data, like the sample in this kit. Only put real student records into AI tools your institution has approved for that data. ACCESS.md covers who approves what.

We already automated this in Power BI or Excel. Is this still useful?

Yes. The rules file and the checks are the point, not the tool. Automation without them is how a wrong comparison goes out every Monday without anyone noticing.

What does "same week of the year" mean?

Weeks numbered the standard international (ISO) way, starting on Monday. Monday of week 46 this year lines up with Monday of week 46 last year, even though the calendar dates differ.

Can I reuse or change this for my school?

Yes. It's MIT licensed. Copy it, rename it, adapt the rules to your own report, and share it with your team.
